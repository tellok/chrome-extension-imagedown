## Context

基线针对提交 `ef31c0a` 的 ImageTaken 0.4.3。原 README 混合使用说明、验收规则、实现细节和历史 UI 描述。仓库此前未使用 OpenSpec，历史提交无法被当成当时已存在的 OpenSpec 变更。

## Goals / Non-Goals

目标是建立当前行为的可测试规范，保留证据，并缩短 README。此次不修改扩展功能、Manifest、默认值、依赖或版本，也不将每个历史 commit 伪造成独立的历史 OpenSpec 归档。

## Decisions

### 一份追溯基线，八份能力规范

以 `document-existing-extension` 记录本次文档整理；八份 delta 同步为 `openspec/specs/` 的当前规范后归档。归档日期采用实际整理日期 2026-10-21；原提交时间在证据表中单独保留。

### 以实现核对历史描述

`ef31c0a` 已把完整原图保存为可复用 Blob，因此原网页导航后不能据此丢弃已持有的数据。`5570a50` 已统一徽标计数，侧栏预览进度不能再覆盖徽标。`ef31c0a` 已将成功图片优先设置改为默认开启。旧版默认关闭、展开后另行累计、粗边四色圆环 Logo 等描述不作为当前约定保留。

### 区分行为规范与开发材料

主规范记录可观察行为、边界和失败处理，不列内部函数或逐步实现。读取策略的技术解释、测试命令和模块索引保存在 `docs/development.md`。素材生成记录继续保存在 `docs/logo.md` 和 `docs/illustrations.md`。README 仅导航到这些资料。

### 阅读流程保留已有实现的区别

完整原文件优先复用；下载需要继续尝试原始字节时，不把像素缩略图误当原文件。重试预览允许先使用已显示像素，原文件下载则优先保留动画。原格式浏览器 URL 下载只作为未持有原文件时的回退，自定义目录不做该回退。

## Risks / Trade-offs

- README 描述可能落后于代码：逐项核对相关源码与测试，将纠正依据记录在 `evidence.md`。
- 追溯不等于历史审批：归档明确标注建档时间与基线提交，不声称曾运行过历史 OpenSpec 流程。
- 规范与归档中存在必要快照重复：主规范是未来维护入口；归档保持本次引入时的记录，不随产品后续迭代修改。

## Migration Plan

读取 README 与 git 历史，撰写能力 delta，精简入口文档，执行严格校验，同步主规范并验证，再将已完成的建档变更归档。此次仅文档和工作流文件变更，无运行数据迁移。回退可恢复 README 并撤回新增文档。
