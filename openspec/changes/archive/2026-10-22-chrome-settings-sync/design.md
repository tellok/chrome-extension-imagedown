# Design

## Context

动机见[proposal](proposal.md)。当前版本为39ba42f，Chrome116+、原生JavaScript模块、零运行时依赖。配置以 `chrome.storage.local` 为运行来源，目录句柄存于本机索引数据库（Indexed Database, IndexedDB），没有配置同步引擎。用户已明确：默认开启、每机独立关闭，搜索词与忽略记录都同步。

### 阅读审计

按配置键、storage.local/sync、设置入口、网站阈值/搜索/忽略、订阅缓存、下载忙碌状态和预计修改路径检索：

- 完整读取直接相关主规格user-preferences、extension-platform、remote-rule-subscriptions，并核对image-filtering、automatic-badge及既有下载批次契约；本提案通过三份MODIFIED显式扩展本机限定，不直接改主规格。
- 基线2026-10-21-document-existing-extension / a7ce2fb的相关proposal、design、delta和tasks确立本机存储、零后端与原图边界；site-specific-image-thresholds / 1d4b551的相关产物确立hostname及字段继承；gallery-threshold-reset-controls / ea3a56f保留显式0、空输入和单项还原。
- remote-rule-subscriptions / 39ba42f的proposal、design、四个相关delta及tasks：有序地址与缓存同存一个键，修改串行化，删除请求不得复活、普通更新复用预览；此次不能直接将整份缓存送入sync。
- add-download-text-manifest / adfa675的相关产物保留清单默认关闭与批次固定。同步可以传输用户选择的开关值，但不会改变出厂值或进行中批次。
- 源码检查preferences.js、settings.js、i18n.js、theme.js、settings-page.js、panel.js、automatic-badge.js、remote-rules*.js、remote-subscriptions.js、background.js、destination.js，及Manifest、README、开发文档、打包与CI；全量测试盘点见[test-review](test-review.md)。

初始main、默认origin/main、工作区干净且活动列表为空；唯一新建chrome-settings-sync。既有提交与旧归档不变。本轮只写规划，业务代码和测试未改。

## Goals / Non-Goals

**Goals:** 保留本机即时响应，在同步副本完整且用户意图明确时才协调；独立设备开关不受复制影响；并发、离线及配额不足均不丢配置。

**Non-Goals:** 不增加账户登录、自有云端、权限或依赖，不自动合并不同字段，不同步本机文件与缓存，不承诺Google云端已送达所有设备，不修改真实用户Chrome或登录测试账户。

## Decisions

### 1. 明确允许表，而不是复制整个local

使用版本1的完整配置载荷（Payload），必需包含settings、sites、subscriptions三个结构段，即使为空也必须存在。字段缺失表示未设置；显式0、false和空字符串保留，不能以真值过滤。

| 结构 | 同步内容 | 校验与排除 |
| --- | --- | --- |
| settings | 语言、主题、标题清洗、成功优先、下载清单、全局默认宽高、全局普通筛选 | 按已支持语言/主题/枚举/数值验证，不同步本机开关；视图对象保留字段存在性 |
| sites | hostname下的宽高体积、XPath、CSS排除、搜索词、忽略摘要集合 | hostname规范化且隔离子域；保留空串/0；忽略只接受已有64位十六进制摘要，集合排序去重；选择器复用本地校验，不套用远程订阅的4KiB字符串限制 |
| subscriptions | 按优先顺序保存的规范化HTTP(S)地址数组 | 使用现有parseSubscription、最多20项、地址唯一；不传输条目标识、文档、时间、错误 |

不使用settings:*等宽泛前缀自动扩展同步范围。内部同步状态、旧未使用全局体积、下载位置修订号、会话数据、目录句柄、图片Blob/Base64、页面标题草稿与下载记录不导出。订阅匹配的有效远程值仍是默认层，不导出为本地网站值。未知字段或无效本地值使该次同步报错，不修剪成另一份配置；本机既有读取容错仍可用。

### 2. 本机开关与协调状态

`settings:chrome-sync`只保存在local，缺失为true，显式false禁用。随机设备UUID及单调计数、共同版本、最后有效云端、待决候选、最近三份选择前备份也只留local；设备UUID不是硬件标识。

后台单例负责协调，状态为禁用、检查中、一致、待同步、待选择、等待完整数据、错误；状态不会作为产品配置再次导出。关闭立即使操作代次失效，取消去抖及重试调度；每次sync API请求和本机应用前再检查开关与代次。已发出的Chrome请求无法撤回，不声称关闭能取消其提交，但不得继续下一阶段或应用旧结果。

重新开启与后台启动、浏览器启动均先比较。开启时注册独立5分钟检查/重试alarm并监听sync事件，本地修改2秒去抖，最多每10秒发布一次，避免持续输入饿死也不逐键写云端。重试必须重新读最新数据；关闭删除本功能alarm，不影响6小时远程订阅刷新。

### 3. 每设备版本，避免并发最后写入获胜

Chrome存储没有跨机器比较交换事务（Compare-And-Swap, CAS）；同一个全局键反复覆盖不能可靠保留同时修改。选择每设备独立命名空间、每revision一个不可变版本头（Version Head），带version、deviceId、随机revision、非负安全整数版本向量（Version Vector）、updatedAt、payloadHash及分片引用。UUID与递增计数决定因果，时间只用于展示。

每次发布只创建本设备新revision的头与新分片，完成前保留旧头；不覆盖单个全局指针。新向量继承已确认/观察的共同版本并递增本机分量。一个版本向量支配另一个表示已包含其因果；不互相支配且内容不同就是并发候选，不能因较晚到达而丢弃。读取所有版本头，选择非被支配前沿；已被完整有效新头支配的旧头无需重新获取其数据，其余不完整头必须等待；前沿配置相同可确认为一致，不同则展示各候选。

本地改动后，只有云端前沿仍对应共同内容、没有未知/不完整候选时自动发布。云端出现不同内容，即使只有云端变化，也按Issue提示用户而不自动导入。无共同版本时，真正空命名空间自动发布本地；内容相同确认；否则提示。存在任何未解析的同步命名空间记录不视为空云端。

保留本机或采用某个候选均是整份选择，新的发布携带已观察前沿的向量联合，解决用户看见的候选。发布期间出现未观察分支时，独立设备头保留它并再次提示。不会自动合并或按时间取胜。

### 4. 分片完整性与配额

确定性JSON编码为UTF-8字节，用SHA-256内容摘要（Content Hash）识别，再Base64分片；每个最终键和值的JSON字节之和不超过7KiB，为Chrome每项8KiB留余量。分片键包含设备UUID、唯一revision和序号，不覆盖旧分片。先写全部新分片，再发布本设备新revision的不可变头，最后读回并核对引用、长度、摘要、schema和字段。必需结构缺失不补默认；乱序到达、缺片、损坏或未知版本只进入等待/错误，不能应用或自动回写。

依据[Chrome storage官方文档](https://developer.chrome.com/docs/extensions/reference/api/storage)：总计102400字节、单项8192字节、最多512项；写频率每分钟120次、每小时1800次。使用Chrome116已有get(null)/getBytesInUse及常量，不使用新版本getKeys。预检包括当前所有sync占用、现有有效头/分片、新分片/头和临时双版本空间；不删除其他设备的头或记录来腾空间。

仅在本设备新头完整读回后，清理它已支配的本设备旧revision头与分片，不删其他设备命名空间。若其他读取者暂时看到旧头而旧分片已释放，其结果是暂缺并保留最后有效本地数据，待新头到达后恢复，不应用半份。中断发布留下的本设备未引用分片可依本机操作记录清理；不猜测或删除其他设备的未完成数据。发布前超配额或实际API失败，保留旧头和本地待同步状态；不截断搜索或忽略记录。可用配置容量小于标称100KB，取决于编码开销、多设备版本与安全更新空间；文档与错误说明这一限制，不承诺无限同步。

Chrome账户未同步时，storage.sync可能只是本机存储；成功状态只说已写入同步存储。跨设备需要相同扩展ID、同一Chrome账户并启用浏览器同步，不新增账户探测或identity权限。

### 5. 共享写入锁与一次本机应用

配置写入使用同源Web锁（Web Locks API）`imagetaken-config-write`。已有destination.js已使用navigator.locks，Chrome目标可复用同一原语；窗口与工作线程可协调，依据[Web Locks规范](https://w3c.github.io/web-locks/)。preferences的写入/删除、设置页语言主题和开关、网站规则应用、后台忽略修改、订阅地址修改及同步应用都接入共享锁。锁内只有本机存储与最终版本检查，不持锁等待HTTP或正则匹配。无浏览器锁的Node单元环境允许直接调用同一回调，真实浏览器用例验证互斥路径。

订阅已使用内部队列，统一顺序为“订阅修改队列→配置写入锁”；标量设置只取配置锁，不反向等待订阅队列，避免死锁。新增内部批量应用入口：在订阅队列内读取最新本机缓存、取得配置锁，再核对界面选择令牌（本地hash及云端前沿revision），不符则返回过期。

一次 `storage.local.set` 写入选择结果、订阅对账后的本机状态、选择前备份和共同版本。被选完整版本中没有、但本地原有的允许字段写入null墓碑（Tombstone），现有读取器把null视为未设置；导出时省略它，不能把它当成0/空字符串。这样无需先remove再set导致多次事件和半导入；既有手动reset仍可remove，不改变其测试契约。该规则属于内部存储兼容处理，不把null放入云端配置字段。

同地址订阅保留本机id、缓存及刷新信息，新增地址生成本机id并在提交后获取，删除地址失效；所有缓存提交和导入共享订阅队列，不允许延迟响应复活删除项。普通配置写入在锁后继续执行，不能被同步导入吞掉。失败不改变本机完整配置或备份；备份仅本机保留最近三份，不新增备份管理产品功能。

### 6. 界面、视图和下载

设置页新增独立同步分类，包含本机开关、范围说明、状态、重试，以及待决时的三项操作。差异按基础设置、网站和订阅分组，展示缺省/显式空/0及各设备候选，长值省略并可展开查看，值仅按文本呈现；不使用系统通知权限或抢占图片徽标。

图库用轻量待决提示进入设置，不弹窗打断选择。同步应用附本机事件标识，面板调用有效配置同步路径，保留成功预览对象、草稿及有效选择；忽略集合另行重读。只有有效XPath/CSS变化才重新采集，徽标比较有效配置后复用普通筛选快照，不因null墓碑或同步元数据本身强制扫描。语言/主题按原事件处理。

已有下载固定items、format、directory、title和manifest；同步变化不能改变这些。范围变化仍由busy机制延后，未来批次使用新设置。七语言、明暗主题与320px保持既有Notion细边框、中性色和轻量说明，不新增设计工具依赖。

### 7. 测试与文档边界

新30项完整清单见[test-review](test-review.md)，18项单元与12项浏览器。浏览器采用两个临时配置的真实Chrome存储，以仅测试夹具中的桥接重排/复制同步键，验证并发、缺片、冲突选择及本机隔离；不触碰真实账户或Chrome资料。不能把这种桥接声称为Google同步服务真实端到端验证。既有67项单元和7个浏览器脚本保持内容不变用于回归，CI新增专项入口。

新增docs/settings-sync.md说明范围、每机关闭、冲突、配额与实际送达边界；README只加短入口并修正“全本机”描述，开发文档记录模块、锁顺序、版本格式和测试命令。无需新运行时依赖、权限或Changeset（仓库未启用）。

## Risks / Trade-offs

- 默认开启会复制域名、搜索词及摘要 → 用户已明确选择，设置范围文案清晰，本机开关从不导出，配置仍可离线使用。
- 多设备版本与双份发布空间消耗配额 → 预检和显式错误，不删有效分支或截断配置；每机可独立关闭。
- 设备停用很久，其头仍占用空间 → 不冒险删除其他设备版本；容量不足反馈，本期不增加设备管理或云端清空入口。
- 事件乱序、后台终止及API请求无法撤回 → 完整引用/摘要、操作代次、先数据后头、重启重新比较，保留本机备份。
- UI编辑与确认竞态 → 共享写锁及决策令牌，过期重比，不持锁联网；无自动字段合并。
- Chrome实际跨设备传输不可在无账户环境断言 → 使用受控桥接只证明扩展逻辑，交付明确外部验证边界。

## Migration Plan

审批当前方案及30项测试后实施。先实现纯编解码/版本比较、共享写锁与引擎，再接入设置/冲突、订阅和视图；分组补齐测试与文档，完成回归及打包后同步主规格、归档并自动提交，提交页脚 `Closes #11`。不自动推送，不改上一提交。

已有配置不清除、不物化默认值。升级首次默认开启：空云端发布，已有不同有效云端提示。回退旧代码忽略新增sync命名空间和本机状态，保留本机配置、目录和缓存；null仍按旧读取器缺省处理。回退版本不会主动停止浏览器自身已排队的同步传输，文档说明本机开关仅控制当前新引擎。
