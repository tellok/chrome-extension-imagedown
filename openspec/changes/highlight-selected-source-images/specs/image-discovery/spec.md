# Spec Delta

## ADDED Requirements

### Requirement: 保留候选与实际页面元素的对应关系

系统 SHALL 为图片选择高亮保留本次扫描中候选与全部可访问承载元素的对应关系，包括同地址多元素、开放影子树（Shadow DOM）和有访问权限的内嵌框架（iframe）。保持已有地址去重、Canvas 独立候选、首个完整溯源记录及读取入口；不将来源描述文本当成唯一元素定位符。只匹配仍属于原文档且仍承载该候选的现存元素，不因标签或地址片段相似误标其他图片。

#### Scenario: 同地址存在多个图片元素
- **WHEN** 主文档、开放子树和可访问框架内多次出现同一完整图片地址，图库选中合并后的一个候选
- **THEN** 所有本次扫描匹配的现存元素均可高亮，图库仍只保留一个地址候选，元数据仍来自首次完整来源

#### Scenario: 多个候选共享承载元素
- **WHEN** 响应式图片的多个候选、或同一元素的不同图片来源被选择，随后取消其中一个候选
- **THEN** 可用承载元素仍被其他选择引用时保持一份高亮，最后一个对应选择取消后去框；picture 中的 source 候选使用所属 img 的可见位置

#### Scenario: 非普通图片与无元素资源
- **WHEN** 选中背景、伪元素、Canvas、内嵌 SVG、视频封面、图片链接或只有资源记录的候选
- **THEN** 有实际承载元素的候选标记其元素范围，只有资源记录的候选不创建虚假位置；不将静态缩略图作为原网页元素或完整原文件

#### Scenario: 原始元素已失效
- **WHEN** 采集后原元素移除、框架导航或资源地址变化，原图库仍持有候选
- **THEN** 旧引用不高亮新文档或替代元素，原有元数据及已取得原文件继续遵循既有生命周期，重新扫描后建立新的元素映射
